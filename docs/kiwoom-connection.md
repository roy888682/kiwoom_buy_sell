# 키움 API 연결 안내

이 프로그램은 키움 공식 REST API의 국내·미국 주식 API 명세를 기준으로 만들었습니다. Windows 전용 OCX나 별도 키움 SDK 없이 HTTP·WebSocket으로 연결합니다. 아래 절차는 연결 방법이며, 이 저장소의 테스트에서 실제 계좌 인증이나 실주문을 수행한 것은 아닙니다.

## 1. 키움에서 사용할 계좌와 키 준비

1. [키움 REST API 공식 사이트](https://openapi.kiwoom.com/main/home)에서 현재 이용 신청, 계좌 연결, 국내·미국 주식 및 시세 이용 조건을 확인합니다.
2. 사용하려는 환경의 App Key와 Secret Key를 발급받습니다. **운영용 키와 모의투자용 키는 서로 다릅니다.**
3. 공식 안내에서 접속 IP 등록을 요구한다면 프로그램이 실행되는 실제 외부 송신 IP를 등록합니다. 클라우드 환경은 프록시의 송신 IP를 사용하거나 IP가 바뀔 수 있으므로 고정 송신 IP와 등록 조건을 확인하세요.
4. 미국 시세 서비스 및 해당 거래소·종목의 실시간 구독 가능 여부를 확인합니다. API 명세에 기능이 있는 것과 자신의 계좌에서 모든 종목을 구독할 수 있는 것은 별개입니다.

키·비밀번호·계좌 DB를 채팅으로 보내거나 저장소에 커밋할 필요는 없습니다. 공식 저장소에 쓰인 환경 변수 이름과 이 프로그램의 이름은 다를 수 있으므로 아래 표를 사용하세요.

## 2. 환경 변수 설정

저장소 최상위에서 `.env.example`을 `.env`로 복사한 뒤 자신의 로컬 편집기나 환경 설정의 비밀 값 입력 기능으로 입력합니다.

| 이름 | 값과 용도 |
| --- | --- |
| `KIWOOM_APP_KEY` | 발급받은 App Key. 국내·미국 조회에 동일 인증 사용 |
| `KIWOOM_SECRET_KEY` | 발급받은 Secret Key |
| `KIWOOM_ENV` | `mock` 또는 `live`. 모의·운영용 키와 일치해야 함 |
| `ALLOW_LIVE_TRADING` | 기본 `false`. 실제 자동 주문을 허용할 때만 `true` |
| `KIWOOM_US_TIMESTAMP_TZ` | 미국 체결 시각의 시간대를 키움과 확인한 뒤에만 지정. 지원 값 `Asia/Seoul`, `America/New_York` |
| `TRADER_DATA_DIR` | 상태 DB 폴더. 기본 `data` |

초기에는 `KIWOOM_ENV=mock`, `ALLOW_LIVE_TRADING=false`를 유지합니다. 실제 키 값은 예제 문서에 넣지 않습니다. 환경 변수로 이미 설정한 값은 `.env`보다 우선합니다. 변경 후 서버를 다시 실행하세요.

대시보드의 **모의 거래**는 이 프로그램 내부의 가상 장부입니다. 키움의 모의투자 서버에 주문하는 모드가 아닙니다. `KIWOOM_ENV=mock`을 설정해도 모의 거래에서 생성한 주문은 키움에 보내지 않습니다. 키가 있으면 해당 서버에서 조회·검색할 수 있지만, 키움 모의 서버의 미국 API·시세 제공 범위는 자신의 계정과 최신 안내로 확인해야 합니다.

실거래 시작은 `KIWOOM_ENV=live`, 운영용 키, `ALLOW_LIVE_TRADING=true`와 화면의 **실거래 시작** 확인 문구가 모두 필요합니다. 이 조건이 없는 상태에서 운영용 키만 입력했다고 주문이 전송되지는 않습니다.

## 3. 네트워크와 조회 확인

사용하는 호스트는 다음과 같습니다. 제한된 클라우드 네트워크에서는 해당 목적지와 WebSocket 연결을 허용해야 합니다.

| 목적 | 호스트 / 프로토콜 |
| --- | --- |
| 운영 REST | `api.kiwoom.com`, HTTPS |
| 모의 REST | `mockapi.kiwoom.com`, HTTPS |
| 운영 실시간 시세 | `api.kiwoom.com`, WSS, 포트 `10000` |
| 모의 실시간 시세 | `mockapi.kiwoom.com`, WSS, 포트 `10000` |
| 공식 신청·문서 | `openapi.kiwoom.com`, HTTPS |

사용 중인 프록시나 방화벽이 HTTP 조회는 허용해도 WSS와 포트 10000을 차단할 수 있습니다. 허용 도메인을 저장한 것만으로 실제 접속이 확인되지는 않습니다. TLS 검증을 끄거나 인증 정보를 우회해서 연결하지 않습니다.

프로그램을 실행하고 정지 상태에서 **시장 탐색**을 누릅니다. 종목 목록, 처리 수, 이력 검증 수와 오류를 확인하세요. 조회가 실패하면 환경 선택과 키, 계좌·시세 권한, 네트워크, 접속 IP 조건을 먼저 확인합니다. 모의 현금이 표시되거나 대시보드가 열렸다는 사실만으로 키움 계좌 연결이 입증되지는 않습니다.

## 4. 전체 시장 이력 준비

국내 KOSPI·KOSDAQ·ETF와 미국 ND·NY·NA 종목 목록을 가져옵니다. 반환된 종목 수와 이력 검증 수는 다를 수 있습니다. 화면의 감시 종목 표시는 최대 250개로 제한되지만, 검색은 전체 반환 목록을 처리합니다.

각 종목은 수정 일봉을 연속 조회하고 다음 조건을 확인합니다.

- 오늘 일봉을 제외하고 전 거래일까지 가격이 있음
- 수정 고가·종가가 유효함
- 검증할 상장일 또는 상장 이후 전체 이력의 명시적 제공자 확인이 있음
- 첫 거래일부터 전 거래일까지 거래소 영업일 이력이 빠지지 않음

연속 조회의 끝에 도달했다는 사실만으로 상장 이후 최고가라고 판단하지 않습니다. 미국 종목 목록에는 검증에 필요한 상장일이 없는 경우가 있어 추가 상장 정보나 완전한 수정 일봉 CSV가 필요합니다. 가져온 CSV는 제공자의 확인에 의존하며 프로그램이 외부에서 독립적으로 진위를 증명한 데이터는 아닙니다.

정지한 상태에서 시장을 국내 또는 미국으로 고르고 CSV를 가져올 수 있습니다. 형식은 [매매 규칙의 CSV 설명](strategy.md#가격-이력-csv)을 참고하세요. 수정 기준일은 가져온 시장의 당일로 기록하며, 거래일 변경 시 다시 준비합니다. 같은 전 거래일이 유지되는 주말·휴일 이후에도 당일 주식 분할 등 가격 조정 기준을 갱신합니다.

## 5. 실시간 구독과 미국 시세 시각

이력 검증이 끝난 종목과 보유 종목을 국내 `0B`, 미국 `FE` 체결 스트림에 등록합니다. 요청 종목 중 일부만 조용히 남기는 방식으로 전체 시장 감시를 가장하지 않습니다. 브로커가 허용하는 종목 수·등록 그룹 수·시세 서비스 범위는 실제 계좌에서 확인해야 합니다.

실시간 구독 승인 수와 요청 수가 맞고 필요한 스트림이 준비된 뒤에 새 돌파를 판단합니다. 첫 수신 시세는 관측 기준값입니다. 연결 끊김, 구독 거절, 처리 대기열 초과 등 시세 공백이 발생하면 자동매매가 정지하며 임의 재주문하지 않습니다.

미국 체결 시각의 시간대는 명세만으로 추측해 지정하지 않습니다. 키움 화면이나 공식 안내와 실제 체결 시각을 대조한 뒤 `KIWOOM_US_TIMESTAMP_TZ`를 설정하세요. 미설정 또는 시각 검증 실패 시 미국 자동 주문을 차단합니다. 현재 시각을 거래 시각으로 대신 붙이거나, 미국 종목이라는 이유로 무조건 뉴욕 시간으로 해석하지 않습니다.

## 6. 실제 주문을 시작할 때

1. 조회, 상장 이후 수정 이력, 시세 시각과 구독 범위를 먼저 확인합니다.
2. 가상 가격으로 돌파·손절·현금 배분 규칙을 확인합니다. 수수료 여유금, 최대 보유 종목 수, 재매수 대기시간을 자신의 계좌에 맞춰 설정합니다.
3. 운영용 키와 `KIWOOM_ENV=live`를 설정하고 실제 주문을 허용할 때만 `ALLOW_LIVE_TRADING=true`로 변경해 재실행합니다.
4. 화면에서 **키움 실거래**를 선택하고 확인 문구를 입력합니다. 계좌의 미체결 주문·현금·실제 보유 수량을 동기화한 뒤 실행합니다.

**이미 계좌에 있는 현금 보유 종목도 자동 손절 대상에 포함됩니다.** 프로그램 전용 계좌를 사용하고, 실행 중 다른 HTS·MTS에서 같은 계좌를 수동으로 거래하지 않는 편이 좋습니다. 계좌와 로컬 체결 장부가 달라지면 자동매매를 정지합니다.

매수는 관측 가격의 지정가 주문이며, 손절은 지원되는 시장가 매도 주문입니다. 주문 접수는 체결이 아닙니다. 부분 체결·체결 평균가·미체결 잔량을 조회해 장부를 갱신합니다. 실제 시세, 주문 거절, 체결 지연을 포함한 운영 검증은 별도로 필요합니다.

## 7. 정지·주문 대조·재시작

**감시 중지**는 자동 손절도 중지합니다. 이미 접수한 미체결 주문은 외부 계좌에 남을 수 있으므로 주문별 취소와 계좌 내역을 확인하세요. 장이 닫혀 있거나 프로그램이 종료된 동안에는 자동 손절 주문을 내지 않습니다.

통신 오류로 접수 여부를 알 수 없으면 주문을 `unknown`으로 보존하고 자동매매를 멈춥니다. 같은 주문을 다시 보내거나 DB를 삭제해 재시작하지 않습니다.

1. 키움 주문 내역에서 종목·매수/매도·주문 수량·주문 번호·주문 일자를 확인합니다.
2. 정지 상태의 주문 내역에서 **주문 번호 · 날짜 대조**를 사용합니다. 전날 주문 등은 키움에 표시된 주문 일자도 입력합니다.
3. 종목·방향·수량이 일치하는 주문만 연결하고 실제 체결과 잔고를 동기화합니다. 필요한 미체결 주문을 취소합니다.
4. 응답 불명·미체결 상태와 계좌 불일치가 해소된 뒤 다시 시작합니다. 재시작 후 첫 가격은 새로운 기준 관측값입니다.

API로 대조해야 하는 경우 `POST /api/orders/{로컬_주문_ID}/bind`의 본문은 `broker_order_id`와 선택적인 `broker_order_date` (`YYYY-MM-DD`)입니다. 비밀번호나 API 키를 이 본문에 넣지 않습니다. 키움 내역에 해당 주문을 찾을 수 없다면 실제 접수 여부부터 확인해야 하며, 자동 재주문으로 해결하지 않습니다.
