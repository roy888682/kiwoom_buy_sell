# 창을 닫아도 PC에서 계속 실행하기

## 실행과 종료

1. 기존에 `start.bat`으로 실행한 검은 창이 있으면 그 창에서 **Ctrl+C**로 종료합니다. 기존 일반 실행은 자동으로 백그라운드로 전환하지 않습니다.
2. 프로그램 폴더의 **`start-background.bat`을 더블클릭**합니다.
3. 준비가 끝나면 브라우저가 열립니다. 화면의 **브라우저를 닫아도 계속 감시하려면**을 눌러 펼치면 **현재 백그라운드 실행 중입니다**라는 안내를 확인할 수 있습니다.
4. **모의 거래 → 실제 시세 모의투자**에서 시장과 설정을 확인하고 **감시 시작**을 누릅니다.
5. 실행 완료 후 처음 열린 명령 창은 종료되어도 괜찮습니다. 브라우저를 닫아도 프로그램은 계속 실행됩니다. 화면을 다시 보고 싶으면 `start-background.bat`을 더블클릭하세요. 실행 중인 서버를 재사용합니다.

감시만 멈추려면 화면의 **감시 중지**를 누릅니다. 프로그램까지 종료하려면 **`stop-background.bat`을 더블클릭**합니다. 종료 요청은 이 폴더에서 실행한 백그라운드 서버만 대상으로 하며, 다른 프로그램을 강제 종료하지 않습니다.

## 자동 복구와 PC 재시작

화면의 **연결 복구 후 자동으로 다시 감시**를 켜고 감시를 시작하면, 통신 오류 후 재시도하고 서버를 다시 켰을 때 저장한 모의 감시 요청을 재개합니다. **감시 중지**는 이 요청도 해제합니다. 재시도 대기 중에는 매수·손절 감시가 멈춰 있습니다. 실거래는 자동으로 재개하지 않습니다.

`stop-background.bat`은 서버를 종료하므로 감시도 중단됩니다. 이후 서버를 다시 켜면 자동 복구가 설정된 모의 감시 요청은 재개될 수 있습니다. 재개를 원하지 않으면 먼저 화면에서 **감시 중지**를 누르세요.

Windows에 로그인할 때 자동으로 켜고 싶다면:

1. `start-background.bat`을 오른쪽 클릭하여 **바로 가기 만들기**를 선택합니다. Windows 11에서는 **추가 옵션 표시** 안에 있을 수 있습니다.
2. **Windows 키 + R**을 누르고 `shell:startup`을 입력합니다.
3. 열린 시작프로그램 폴더에 방금 만든 **바로 가기**를 옮깁니다. 원본 프로그램 파일을 옮기지 않습니다.

이는 **로그인 후 실행**입니다. 로그아웃 상태에서도 부팅 직후 실행해야 한다면 Windows 서비스나 별도 상시 서버 구성이 필요합니다. 서버 프로세스 자체가 비정상 종료한 경우에는 실행 파일을 다시 열어야 합니다. 연결 오류에 대한 자동 복구와 서버 프로세스의 재시작은 별개의 기능입니다.

## 계속 켜두기 위한 조건

- PC 전원과 인터넷 연결을 유지합니다. 절전·최대 절전 중에는 시세를 받지 못합니다. 화면만 꺼지는 것은 괜찮습니다.
- 거래소 장이 열리고 검증 가능한 새 시세가 들어올 때만 모의 주문을 계산합니다. 장외·휴장·키움 점검 때 억지로 거래를 만들지 않습니다.
- 공유기 공인 IP가 바뀌면 키움 접속 IP 등록을 다시 확인해야 할 수 있습니다.
- 브라우저 주소는 기본 8000번이며, 사용 중인 경우 선택된 다른 포트가 자동으로 열립니다.

실행 오류는 프로그램 폴더의 **`.runtime/background-날짜-시간-임의문자.log`**에 기록됩니다. 실행할 때마다 새 파일을 만들며, 기존 실행 기록은 다시 열거나 덮어쓰지 않습니다. 오류 확인 시 `.runtime` 폴더에서 수정한 날짜가 가장 최근인 로그를 확인하세요. `.runtime`은 Git에 올리지 않는 로컬 실행 정보 폴더입니다. 로그에는 민감한 계좌 정보가 포함될 수 있으므로 전체 파일을 공개하지 마세요.

### 이전 버전에서 background.log 접근 거부가 나타날 때

`Permission denied: ...\.runtime\background.log`는 실행 기록 파일 접근에 실패했다는 뜻입니다. 해당 문구만으로 파일 잠금, 읽기 전용 속성, 폴더 권한 중 어느 것이 원인인지 확정할 수는 없습니다.

최신 `background.py`로 업데이트하면 이전 `background.log`를 열지 않고 새 실행 기록을 사용합니다. `.env`나 `data`를 지우거나 이전 로그를 강제로 삭제할 필요가 없습니다. 업데이트한 뒤 `start-background.bat`을 다시 실행하세요.

새 로그 파일도 만들 수 없다는 안내가 나오면 `.runtime` 폴더의 쓰기 권한과 Windows 보안의 폴더 보호 알림을 확인해야 합니다.

## GitHub와 별도 서버

GitHub 저장소는 코드를 보관합니다. GitHub Actions는 실행 시간 제한·임시 실행 환경·송신 IP 특성 때문에 24시간 상시 감시 서버로 적합하지 않습니다.

PC 전원을 꺼두고 감시하려면 별도 서버/VPS가 필요합니다. 해당 서버에 코드를 설치하고 키움 접속 IP와 시세 권한을 확인해야 합니다. 이 작업에서 외부 유료 서버를 만들거나 배포하지는 않았습니다. 웹 화면에는 로그인 기능이 없으므로 공개 인터넷에 포트를 열지 않고, `127.0.0.1` 바인딩과 SSH 터널을 사용합니다.
